Что такое ServiceHub
Мы делаем внутреннюю ITSM/Service Desk систему для компании, которая обслуживает корпоративную IT-инфраструктуру клиентов.
То есть ServiceHub — не сайт для обычных пользователей и не интернет-магазин.
Есть компании-клиенты, у каждой могут быть:
- офисы / площадки;
- контакты;
- договоры;
- оборудование;
- IT-инфраструктура.
А сотрудники нашей сервисной компании обслуживают всё это через ServiceHub.
Например:
ООО «Альфа» сообщает: «На втором этаже не работает Wi-Fi».

Сотрудник создаёт заявку → заявка привязывается к компании и площадке → назначается инженер → инженер работает с заявкой → оставляет комментарии → меняет статус → проблема решена.

Кто пользователи ServiceHub
У нас четыре основные роли.
👨‍💼 Manager
Менеджер работает с клиентами.
Ему нужны:
- компании;
- контакты;
- площадки;
- договоры;
- заявки;
- информация о состоянии обслуживания.
Например:
«Что сейчас происходит у компании Альфа? Какие у них открытые заявки? Когда заканчивается договор?»

Engineer
Инженер — тот, кто непосредственно обслуживает инфраструктуру.
Ему важнее всего:
- мои заявки;
- заявки;
- устройства;
- площадки;
- история оборудования;
- комментарии;
- изменение статуса заявки.
Например:
«У меня заявка №102. Офис Альфы, второй этаж. Нужно проверить Wi-Fi точку.»


Leader
Руководитель инженерной команды.
Ему нужно видеть:
- все заявки;
- кто чем занят;
- просроченные заявки;
- загрузку инженеров;
- историю работы;
- состояние инфраструктуры.
То есть Dashboard для Leader будет гораздо интереснее, чем для Engineer.

Administrator
Администратор системы:
- пользователи;
- роли;
- permissions;
- настройки.
Ему не обязательно заниматься заявками каждый день.

У нас есть три уровня объектов.
